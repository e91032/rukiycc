# 拉密

拉密（Rummikub）的網頁版，兩個檔案，沒有建置流程也沒有相依套件。

- `index.html` — 單人挑戰，離線可玩。
- `duel.html` — 兩人連線對戰，走 WebRTC 點對點。

## 上傳到 GitHub Pages

1. 開一個新的 repository。
2. 把 `index.html` 和 `duel.html` 放進根目錄，commit 之後 push。
3. 到 repository 的 Settings → Pages，Source 選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)`，存檔。
4. 等一兩分鐘，網址會是 `https://<你的帳號>.github.io/<repo 名稱>/`，連線對戰在 `/duel.html`。

首頁的檔名一定要是 `index.html`，GitHub Pages 才會認。

## 手機

兩個頁面都是為手機排的：操作按鈕固定兩排、不用橫捲，主要動作在上排；牌在窄螢幕會自動放大好點；長順子在桌面區內單獨左右滑，不會撐破版面；版面高度跟著瀏覽器工具列伸縮，底部按鈕不會被壓住。深色模式跟系統設定走。

用 Safari 或 Chrome 的「加入主畫面」可以當成 app 開，會去掉網址列。

## 單人玩法

106 張牌：紅、藍、黑、橘各 1–13 兩套，加 2 張鬼牌。起手 14 張，目標是把手牌全部打完。

- **有效組合**：順子（同色連續 3 張以上）或同數組（同數字、不同顏色 3–4 張）。
- **破冰**：第一次下牌必須一次打出合計門檻分數以上，而且只能用自己的手牌。門檻預設 30 分，可以在「玩法」面板裡改成 50 分，或直接關掉。
- **破冰之後**：桌面開放，可以拆開重組任何一組，只要回合結束時每組都成立、且至少放下 1 張手牌。
- **鬼牌**：代替任何一張牌，自動算成對你最有利的數字。
- **抽牌**：代表這回合放棄出牌，桌面會還原。牌堆抽完還沒出完手牌，這局就結束。

破冰門檻有三檔：關掉（湊出任何一組就能放上桌）、30 分（標準規則）、50 分（開局要忍更久）。最佳回合數的紀錄是分門檻各記各的，不會互相汙染。連線對戰的門檻由開房的人決定，對手會在大廳看到是哪一檔。

操作是點選式的：點牌選取，再按「排成新組合」或某組的「加入這組」。這回合剛放上桌的牌（底下有金線）可以按「收回手上」拿回來。

## 幾件實作上的事

- **紀錄存在瀏覽器裡。** 最佳回合數用 `localStorage` 存，換裝置或清除資料就會不見。不會傳到任何地方。
- **唯一的外部請求是字型。** 頁面從 Google Fonts 載 Archivo 和 Noto Sans TC。斷網或不想要外連的話，把 `<head>` 裡那三行 `<link>` 刪掉即可，會退回系統字型，功能完全不受影響。
- **深色模式**跟著系統設定走。

## 連線對戰（`duel.html`）

兩個人各自用自己的裝置玩，走 WebRTC 點對點連線。

- 一個人按「開新房間」，拿到一組 4 碼房號（例如 `K7P2`），也可以複製邀請連結。
- 另一個人輸入房號，或直接開邀請連結（網址後面的 `#K7P2` 會自動填入）。
- 連上之後，兩台裝置直接對連，牌局資料不經過任何伺服器。

開房的人是莊家，整副牌和雙方手牌都在他的瀏覽器裡；客人只會收到自己的手牌和桌面，看不到莊家手上有什麼。所有出牌都由莊家端驗證——牌張數量對不上、組合不成立、破冰不滿 30 分，都會被退回。

### 兩件要知道的事

**必須是 HTTPS。** WebRTC 在 `http://` 或 `file://` 下多數瀏覽器會擋。GitHub Pages 本來就是 HTTPS，直接用沒問題；本機測試請用 `localhost`（也被視為安全來源），不要直接雙擊開檔案。

**牽線要靠外部服務。** 兩台裝置要先交換連線資訊才連得上，這一步用的是 PeerJS 的公開 broker（`0.peerjs.com`）。它是免費的公共服務，偶爾會忙線或連不上，這時候重開房間再試。牌局本身完全不經過它。另外頁面會從 jsDelivr 載入 `peerjs@1.5.5`。

### 其他限制

- 莊家關掉頁面，這局就結束了，沒有存檔。
- 一間房只收一個客人，第二個連進來的會被拒絕。
- 斷線之後沒有自動重連，得重新開房。
- 房號只有 4 碼，而且是公用 broker，理論上有人能猜中房號插進來。玩個拉密沒差，但心裡有數。
